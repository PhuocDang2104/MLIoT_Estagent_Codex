## Contract decisions for this card

- Preserve all current API routes and valid `checkpoint-tour-v1` manifests. Old `audio.status=unavailable`
  with null tracks remains valid. Add audio metadata only; schema and fixtures updated together.
- Small first implementation may support **PCM WAV only** with explicit UI/error; Python stdlib `wave`
  validates actual bytes, channels/sample width/rate/duration. Do not accept a file just because browser duration/MIME says audio.
- Per-track <=20 MB, <=180 seconds, accepted sample rate/channel ranges documented; no ffmpeg/decoder/new dependency without NEED.
- Music optional; narration belongs to a scene and the tour source locale. Store stable asset refs, source/rights declaration,
  measured duration, not user URLs/paths/base64. Draft owner only can upload/attach/edit.
- A new explicit attachment/update increments revision and clears review. Publish uses reviewed revision,
  verifies referenced assets and freezes refs; later draft edits cannot alter published audio.
- Private audio endpoints check session ownership; published reads only allow assets belonging to that snapshot.
  Never accept arbitrary path/URL, fetch external media, overwrite old audio blobs or expose draft audio publicly.
- Report music/narration availability accurately per scene. Do not make absent narration a silent success.
- No key/TTS calls, no downloading/licensing music. Tests may generate synthetic PCM tracks, labelled as tones,
  not human speech/music assets. App supports user-authorized real recordings; no demo audio must be fabricated.
